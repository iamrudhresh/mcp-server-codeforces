Core capabilities

Everything a competitive programmer asks about

A

Problemset search

Find problems by id (158A), title, tag or rating. Multi-word queries use AND semantics, so dp 1500 means exactly that.

↗

Rating history & analytics

Per-contest deltas, best rating, biggest swing, acceptance rate, verdict mix, favourite languages, strongest tags and a solved-by-rating curve.

#1

Contests & standings

Upcoming rounds with hours-to-start, standings windows filtered by handle, post-contest rating changes and per-contest submissions.

✓

Read-only by construction

No login, no cookies, no code execution, no submissions. get_capabilities states the contract so agents never try.

⌛

Rate-limit aware

A serialized throttle, TTL cache and exponential backoff on Call limit exceeded, 429, 5xx and timeouts keep you inside Codeforces' limits.

{}

Context-window safe

The 20 MB problemset, 26 MB rated list and full standings are normalized and capped. Submissions are compacted to the fields that matter.

Node.js runtime — src/

  • server.js · STDIO entrypoint
  • tools.js · 17 registrations
  • api.js · operations & analytics
  • http.js · throttle, cache, retries
  • normalize.js · pure scoring

Python runtime — app/

  • run_server.py · STDIO or --http
  • tools/*.py · FastMCP registrations
  • client/api.py · mirrors api.js
  • client/http.py · async httpx client
  • main.py · Streamable HTTP ASGI app

Quality

Hardened against real API quirks

Notable fixes

  • ✓English names — Codeforces answers in Russian unless lang=en is sent.
  • ✓Standings work anonymously — extra params are rejected upstream, so paging is done locally.
  • ✓Unbounded leaderboard and contest payloads are capped.
  • ✓Concurrent calls can no longer slip past the rate limiter.
  • ✓Searching 1500 returns 1500-rated problems, not contest 1500.
  • ✓One shared HTTP client, reused and closed cleanly; zero unpublished dependencies.
